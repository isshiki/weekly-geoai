# 初心者向け活用事例の週次収集

[読者像の正本](audience-and-positioning.md)に基づき、毎週水曜9時（日本時間）に仕事・暮らしでのGIS/GeoAI活用を収集する。日次提供記事への追加検索、木曜の参考媒体ウォッチ、月初月曜のAtlas保守とは別の役割である。

2026-10-31設定済み：アプリの定期実行「GIS・GeoAIの身近な活用事例収集」（ID: `gis-geoai`）。木曜の既存ウォッチ（ID: `geoai-2`）も正式な読者像と水曜候補の参照に更新した。実行環境の稼働・利用可能な接続に依存するため、設定済みと実行成功は区別する。

## 対象と出典

- 店舗候補地の比較、配送状況の共有、生活施設へのアクセス、防災、地域の人口・公共施設など、初心者にも目的が分かる例を優先する。
- 国土交通省・国土地理院・自治体の公開資料、QGIS/OSGeoの公開発表や利用者の作品、ベンダーの導入事例を探す。
- 国内参考媒体： [PSSのGeoAIマガジン](https://note.com/pacificspatial/m/mc7dbe40899e9)、[厳網林のnote](https://note.com/geoai)、[宙畑](https://sorabatake.jp/tag/geoai/)。ニュースレターと解説連載は区別し、可能なら原典へ進む。
- コミュニティの入口： [QGIS User Group Japan](https://qgis.jp/)、[QGISのconnpass](https://qgis.connpass.com/)、[OSGeo日本支部](https://osgeojp.connpass.com/)。活動日・対象者・参加条件を確認し、古い催しを募集中と書かない。

## 収集から保守まで

1. 既存の日次ログ・Atlas・候補メモと重複を確認する。1回0〜3件でよく、収穫なしも正常とする。ニュースと違い古い良質な基礎例も可だが、公開日と確認日を分ける。
2. 「困っている人／したいこと／地図でできること／必要な情報／AIが助ける部分（なければなし）／分からないこと／原典URL」を短く記録する。
3. 架空の説明例と実際の導入事例を明示する。企業による効果主張を独立検証済みとしない。位置追跡にはデータ取得の仕組みが要るなど、導入判断に必要な条件は保持する。
4. 有用な候補だけ `editorial/usecase-candidates/YYYY-MM-DD.md` に公開可能な要約で保存する。原文・社内事情・個人情報は保存しない。未確認の候補は確認範囲と未確認点を明記する。空ファイルを作らない。
5. 長期的に役立ち、出典を確認できた内容は既存のAtlasのcases/guidesへ最大1テーマを目安に統合する。新ページは既存に収まらない場合のみ。公開URL・分類を保ち、導線、確認台帳、更新履歴のハイライトを通常のAtlas運用に沿って更新する。
6. リポジトリの変更は関連する検証・公開情報チェック後に対象差分をコミット・プッシュし、サイト変更時はデプロイを確認する。ニュースレターへの採用・Substack投稿は自動化しない。
7. 新しい有用な候補、意味のあるAtlas改善、失敗や要対応事項だけ短く通知する。既出・更新なしは静かに終了する。

図版は役に立つ時だけ追加する。既存の専門解説を薄めず、利用場面から読み始める入口を補う。再配布権のない画像や書籍の図版をコピーしない。
