# DuckDBとSpatial拡張

DuckDBは、手元やクラウドの表データをSQLで集計する分析用データベースである。Spatial拡張を組み合わせると、地点と区域の照合、距離、座標変換などの地理空間処理を扱える。CLIやPythonなどの実行環境と、SQLの基本知識が必要になる。

## 現在確認している機能

2026-10-30に確認した2.0の情報を基準とする。GIS機能が2.0で初めて追加されたわけではない。

| やりたいこと | 機能と確認点 |
| --- | --- |
| POIや地域別データを集計する | ファイルをSQLで絞り込み・集約する。クラウド読み込みと空間演算の性能は分けて測る |
| 座標系の違う図形を扱う | 1.5で本体に入ったGEOMETRY型はCRSを指定できる。型の指定と座標値の変換は別の操作 |
| 区域・距離などで分析する | Spatial拡張の空間関数を使う。導入後もLOAD spatialによる明示的な読み込みが必要 |
| 分析結果をWeb地図へ渡す | 2.0ではGeoJSON／GeoJSONLへ直接書き出せる |
| AIエージェントから使う | 2.0のagent modeはCLI出力を簡潔にする機能。AIが分析の正しさを保証する機能ではない |

## 導入・更新時の注意

- **座標軸の扱い**：1.5発表は、対象関数でgeometry_always_xy未指定時の警告を2.0でエラーにすると案内している。経度・緯度の順を確認し、既存処理を保つか新しい扱いにするかを明示する。設定変更だけでなく既知地点の位置・距離を確認する。
- **DB形式**：2.0で新しく作るDBを1.xから直接開けるとは限らない。既存形式のファイルを2.0で扱う場合と、新規作成を分けて移行を判断する。
- **拡張と本体**：GEOMETRYが本体にあっても、すべての空間処理が拡張なしで使えるわけではない。
- **性能**：読込、集計、空間結合、キャッシュの条件を分ける。他の記事の秒数を自分の環境での保証値にしない。
