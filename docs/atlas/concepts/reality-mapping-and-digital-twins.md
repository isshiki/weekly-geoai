# リアリティーマッピングとデジタルツイン

リアリティーマッピングは、特定時点の現実空間を地理空間的に正確な3Dモデルや地図として再現する技術である。デジタルツインは、そのような現況データにセンサーや業務データを組み合わせ、継続的に更新しながら監視、分析、意思決定に使うモデルである。

## ファイル変換の前に四つの対応を決める

同じ建物を表示できても、分析に必要な情報が引き継がれるとは限らない。PSSの統合解説では、次の違いを整理している。

| 観点 | 統合前に確認すること |
| --- | --- |
| 座標 | 建物の原点・向き・高さを地球上の位置・標高へ結び付ける |
| 細かさ | 景観なら外観、避難なら部屋や接続など、目的に必要な情報を選ぶ |
| 意味 | 厚みのある部材と外壁面など、同じ名称でも表す対象が違う |
| 運用 | 誰が更新し、どの時点のデータをサービスへ渡すか決める |

形式の読み込み成功だけで統合完了としない。「何のためにつなぐか」を先に決め、削った情報と残した情報を確認する。[BIMとGISはなぜつながりにくいのか](https://note.com/pacificspatial/n/nec0da62e2334)（11月9日公開、2026-11-10にnote公式APIで本文確認。変換試験は未実施）。


## 確認したポイント

- リアリティーマッピングの成果物には、トゥルーオルソ、点群、3Dメッシュ、標高モデル、方向付き画像などがある。
- 両者の違いは見た目の精細さではなく、時間的な更新性と利用目的にある。
- リアリティーマッピングの成果物は、デジタルツインを構成する基盤データまたはビジュアルレイヤーになり得る。

## BIMとGISをつなぐ目的

建物の設備や部屋を知りたいのか、周囲の道路・地形・災害リスクと一緒に見たいのかで、必要な情報の細かさが変わる。Pacific Spatial Solutionsの歴史解説は、BIMが建物内部や部材を詳しく記述する方向、GISが広い地域の情報を重ねて分析する方向に発展したと整理する。

この整理は学習の入口であり、現在のGISが建物内部を扱えないという制約ではない。例えば建物と周辺の浸水区域を重ねる場合、立体表示をそろえるだけでなく、位置・高さの基準、部材と建物の対応、データの時点を確認する。GISを「場所に属性を結び付けたデータベース」と捉えると、統合する情報の目的を考えやすい。

[GISの歩み：地図から「場所のデータベース」へ](https://note.com/pacificspatial/n/nba4df01d6e8f)（2026-11-07公開、2026-11-08にnote公式APIで本文確認。統合時の確認例はAtlasの説明用）

## 建物の高さと階数の定義を合わせる

建物を階数から立体化する際は、「高さ」が軒先・屋根の頂部のどちらまでか、「階数」が屋根裏を含むかを確認する。天井高、床から次の床までの高さ、建物全体の高さを階数で割った値は同じではない。

TerraLabのフランス10自治体の分析では、2階以上の243,603棟で高さ／階数の中央値が3.07mだった。ただし高さは軒先までで、階数には屋根裏を含み得る。これは著者のデータ比較であり、各階を実測した普遍的な換算係数ではない。用途や地域が異なる3Dモデルへ一律に適用しない。
