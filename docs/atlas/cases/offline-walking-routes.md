# オフライン徒歩経路と施設入口

通信できない場所でも、地図と道路の接続情報を端末へ保存しておけば、端末内で経路を計算する構成を取れる。ただし「経路を計算できる」と「現地で安全に通れる」は別である。

## おすそぐら避難所マップの制作例

作者の2026年11月1日の記事は、OSMの地図・道路と国土地理院の避難場所データを事前保存するiOSアプリを紹介する。機内モードでも徒歩経路を生成する設計である。以下は作者の報告であり、Atlasでの動作再現ではない。

| 必要な情報 | なぜ必要か |
| --- | --- |
| 道路の形状と接続 | 地図上で線が交わって見えても、立体交差などでは曲がれない |
| 歩行者の通行条件 | 道路の種類だけでなく、歩行者や私有地へのアクセス制限も関わる |
| 施設入口と敷地内通路 | 公園や学校の代表点は入口とは限らず、入口と道路の接続も必要 |
| データの時点 | 保存後の災害による損傷や通行止めは保存データから分からない |

## 検証から分かること

作者は都心5区の16ケースで経路生成に成功したと報告する。これとは別に、千代田区の20施設へ四方向から近づく80ケースで、代表点を目的地にすると入口指定より平均81m、最大415m長い経路になった。全国の経路品質を保証する結果ではない。

この例は、POIの「施設の位置」と徒歩経路の「到着したい入口」を分ける理由になる。災害時の現況は別途確認が必要で、記事でも経路を参考情報として扱っている。
