# オープンな基盤地図データと共同整備

建物・道路・施設・住所などの基礎データを共通基盤として整備し、その上に業務固有の情報を重ねる考え方である。Overture Maps FoundationのWill Mortensonは2026年9月24日の論考で、行政と企業が基盤データを共同で整備・利用するよう提案した。

## 論考が挙げる論点

- データの信頼性を作成主体だけで判断せず、精度・鮮度・相互運用性・利用目的への適合から評価する。
- 部署ごとの重複調達や、他機関への共有を妨げる条件を見直す。
- 共通の基盤を共同で更新し、各組織は自分たちの業務に必要な情報へ投資する。

これはOverture側の提言であり、すべての行政データより民間データの方が優れているという比較結果ではない。また、個別データのライセンスや帰属表示の条件がなくなることを意味しない。

## 利用側で残したい情報

以下はAtlasの実務上の整理である。共通データを使う場合も、取得版、対象範囲、出所、更新時点、独自に加工した内容を残す。同じ基盤を使っていても、取得時点や施設分類が違えば分析結果は一致しない。

## 建物データは面積と一棟の単位を分けて比べる

建物ポリゴンは、総面積が近くても棟ごとの分割や抜けが異なる。TerraLabのVitré（フランス、2.2km²）の比較では、参照建物とIoU（重なり面積／和集合面積）が0.5超となる割合はOSM83%、Overture84%、Microsoft25%だった。Microsoftでは複数の家が一つのポリゴンにまとまる例がある。

参照したIGNの建物とOSMには地籍由来の情報が含まれ、完全に独立した正解との比較ではない。棟数、分割単位、重なり、データの来歴を一緒に見る。一地区の結果から国全体や全用途での優劣を決めず、面積を測る用途と一棟ずつ数える用途も分ける。

### 日本の建物：形があることと、属性があること

Toru Mori氏の2026年11月17日の分析は、Overtureの2026-10-21.0版で日本の建物約5,400万件を集計した。OSM由来が約55％、Microsoftの機械学習データが約39％、Zenodoで公開された東アジアの研究データが約6％だった。全国値は建物の外接矩形の中心を0.01度グリッドへ集計し、都道府県範囲に対応付けた概数である。

草加市では収録建物がOSM由来分の約11倍あり、未整備地域を機械学習由来の形状が補う様子を示す。ただし、現地の全建物を確認した網羅率ではない。同市と足立区の集計は建物の重心で区域を判定している。

筆者の日本の集計では、高さ・用途などの属性はOSM由来に限られ、OSM由来でも高さがあるのは14.1％だった。建物の分布を見る用途と、高さから立体表示したり用途別に数えたりする用途では、使える対象が異なる。高さの欠損を0m、用途の欠損を住宅と読み替えず、属性のある割合をソース別に確認する。

これは対象版の分析結果で、全世界・将来の版にも属性がOSM由来だけという意味ではない。公式ガイドはOSMを優先して他ソースで補う構成に加え、対応する建物間で高さ属性を統合する仕組みも説明している。記事ではOSMの収録時点と公開日のずれ、MLの元画像より後に取り壊された建物が残る可能性も指摘する。データの版だけでなく、元情報の時点も確認する。Atlasでは再集計や公開地図の操作検証は行っていない。

## OSMの道具を目的別に探す

Awesome OpenStreetMapは、OSMの利用と共同編集を支える道具のリンク集である。初めて探す場合は、何をしたいかで入口を選ぶ。

| したいこと | 掲載されている例 |
| --- | --- |
| 地物を編集する | iD、JOSM、StreetComplete、Vespucci |
| 条件に合うデータを探す | overpass-turbo |
| データの問題を確認する | Osmose |
| タグの使われ方を調べる | taginfo |
| アプリへ組み込む | 言語別ライブラリ、地図・経路案内、公開APIの一覧 |

保守されていないプロジェクトは別リストに分けられている。掲載先で最終更新、対応環境、利用条件を確認し、一覧への掲載だけを推奨や動作保証と受け取らない。各ツールの操作は本Atlasでは未検証である。
