# ハザードデータの再利用条件

ハザードマップをプログラムへ取り込む際は、表示できる地図と、再利用可能なデータを区別する。避難経路OSSの開発報告は、次の3条件を確認する必要を示している。

| 確認対象 | 開発報告で直面した問題 |
| --- | --- |
| 形式 | PDFやWebGISは見つかっても、読み込める一次データへのリンクが確認できない場合がある |
| 属性定義 | 松戸市のデータではDEPTHが連続値で、RANKとの対応を観測できても公式定義を確認できなかった |
| 利用条件 | データを取得できることと、OSSでの二次利用条件を確認できたことは異なる |

## 報告の範囲

2026年9月17日の記事は、ダミーデータでの実装後、実データによる検証を保留した報告である。0.5mという危険判定の閾値は著者のプロトタイプ上の設計判断で、公的な避難基準ではない。

この記事だけから、各自治体のデータが利用禁止である、機械可読データが存在しない、あるいは提示経路が安全であるとは判断できない。利用条件が未確認の状態と、利用不可が確認された状態を分けて管理する点が参考になる。

## PNGタイルから読み取れる範囲

PNGの色を凡例と照合する方法では、元の地物を取得せずに表示上の区分を読める。ただし、透明な画素から「区域外」と「データ未整備」を見分けることはできない。Pohodaの実装報告は、この不確実性を結果の状態として残している。

| 表示状態 | 記事の基本的な扱い |
| --- | --- |
| 区域内 | 不透明で確認済みの凡例色と一致した画素からランクを読む |
| 境界付近 | 半透明・凡例外・未確認色などを確定判定と分ける。必ずしも実際の境界を意味しない |
| 表示なし | 透明・404。区域外や未整備のどちらかは判定しない |
| エラー | 通信失敗や凡例の不備。表示なしと混同しない |

レイヤー固有の模様・半透明の扱いには例外がある。記事では番地までの住所は1画素、町名・駅名などは代表点の周囲300mを評価し、未取得タイルが残る場合は取得済みの部分だけで結果を返さない。これは著者の設計であり、公的な安全判定の基準ではない。

SwiftとJavaScriptの共通凡例を用い、27地点などで検証したと報告しているが、浸水深20m以上などの色は未確認である。本Atlasでは実装を再実行していない。
