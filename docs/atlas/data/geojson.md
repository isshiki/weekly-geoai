# GeoJSON：位置と形を交換する形式

GeoJSONは、地図上の点・線・面とその属性をJSONというテキスト形式で交換するための仕様である。店舗の位置、歩く経路、公園の範囲などをWeb地図やGISへ渡す場面で使う。AIモデルや分析手法そのものではない。

## 形と説明を分けて持つ

| 要素 | 役割 | 例 |
| --- | --- | --- |
| Geometry | 位置と形 | 店舗のPoint、経路のLineString、公園範囲のPolygon |
| Feature | geometryとpropertiesを組み合わせた1件 | 店舗の位置と名前・分類 |
| FeatureCollection | 複数のFeatureの集まり | 複数店舗・経路・範囲をまとめたデータ |

propertiesは属性を入れる場所であり、同じキー名でも意味や単位が揃っているとは限らない。Polygonは輪郭の始点と終点を一致させる。四角形なら四隅と始点の繰り返しで5組になる。

## 座標の意味を確認する

現行のRFC 7946はWGS 84の十進度で、座標は経度、緯度の順である。別の座標参照系の数値をそのまま入れない。古い仕様で使われたcrsメンバーによる座標系指定とは区別する。読みやすくWebで交換しやすい一方、大量データではサイズや取得方法も考慮する。

## 読めることと正しいことは違う

| 検証段階 | 主な問い | それだけでは分からないこと |
| --- | --- | --- |
| JSON構文 | 括弧・区切りなどを読めるか | GeoJSONの構造や位置 |
| 基本構造 | type・配列・輪郭の閉鎖などが合うか | 自己交差や現実の対象 |
| 幾何形状 | 自己交差などの問題がないか | 座標順・想定地域・鮮度 |
| 座標と内容 | 想定した場所か、出典や属性が妥当か | 現地状況との完全な一致 |

一色政彦の記事は、Python 3.14.0、GeoPandas 1.1.4、Shapely 2.1.2、pyogrio 0.13.0、GDAL 3.12.4で架空の点・線・面を検証している。座標を逆にした点もis_validが真になり、未閉鎖Polygonはfrom_featuresでは補完され、read_fileではエラーになった。これは記事の環境での測定であり、全版・全入力での挙動ではない。本Atlasでは再実行していない。

保存後の再読込と形状・属性の照合に加え、出力された座標とcrsメンバーの有無も確認する。描画できることだけでも内容の正しさは保証されない。
