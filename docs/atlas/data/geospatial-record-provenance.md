# 地理空間データの来歴とレコード単位のメタデータ

地理空間データの来歴は、どこから取得し、どう作り、どの変換を経たかを示す情報である。AIが個々のレコードを抽出・再結合する場合、データセット全体に付けた説明だけでは、その情報が結果へ引き継がれないことがある。

## 入力・処理・出力をつなぐ

W3CのPROVは、データなどの実体（Entity）、生成や変換の活動（Activity）、関与する人・組織・ソフトウェアなどの主体（Agent）の関係で来歴を表す。作成者名だけを付けるのではなく、どの入力から何を経て結果ができたかをたどれるようにする考え方である。

例えば「店舗データのある版 → 対象業種の抽出と区域への結合 → 区域別件数」という流れを記録する。件数だけを保存すると、データが更新されたのか、カテゴリや境界の扱いを変えたのか判別しにくい。

## 最小限の作業記録

以下はAtlasで勧める実務上の記録例であり、PROVの必須項目一覧ではない。

| 段階 | 残すもの |
| --- | --- |
| 入力 | 出典URL、取得日、データの版、対象範囲、利用条件 |
| 処理 | コードの版、実行環境、CRS、抽出条件、結合条件、重複・欠損の扱い |
| 出力 | 出力名、作成日、入力件数、対応済み一意件数、未所属・複数所属の件数 |
| 検証 | 期待値との照合結果、未確認の範囲、担当者や実行主体 |

原本と加工後のファイルを区別し、同じ処理へ戻れる対応を残す。記録がそろっていても、入力データや推計自体の正しさを保証するわけではない。公開する記録へAPIキーや個人の移動履歴を含めず、必要な参照情報とアクセス制御を分ける。

## レコードと一緒に保持する情報

| 情報 | 確認したい内容 |
| --- | --- |
| 識別子 | 元の地物や過去の版との対応 |
| 出所・生成方法 | 現地測量、画像からの機械学習抽出など |
| 利用条件 | 再利用や他データとの組み合わせに関する制約 |
| 座標参照系 | 実世界の位置への対応 |
| 処理履歴 | 変換や属性追加の経緯 |

2026年9月17日のOvertureの記事は、GERSの永続ID、共通スキーマへの検証・統合、機械可読形式を関連付けている。すべての処理を通じてメタデータを保持することは同団体が示す目標であり、全レコードに必要な情報が揃っていることの保証ではない。
