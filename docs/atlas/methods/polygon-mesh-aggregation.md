# ポリゴンのメッシュ集計と被覆率

ポリゴンを共通メッシュへ集計するときは、判定対象、面積の重複、属性値の意味を分ける。防災DBの実装解説は、洪水区域を例にBigQueryでの違いを示す。

## 交差と面積の違い

| 判定・値 | 表すもの |
| --- | --- |
| 中心点の内外 | 代表点が区域内か。メッシュの端の重なりは拾わない |
| ST_INTERSECTS | 共通の点があるか。境界だけの接触も含む |
| 交差面積が正 | 面として重なる部分があるか |
| 浸水深区分下限のMAX | 重なる区域の最も大きい区分下限。平均浸水深ではない |

## 被覆率では重複を除く

同じメッシュの80％と70％を覆う区域が60％重複する場合、和集合は90％である。単純合計150％を100％で打ち切っても二重計上は解消しない。記事は`ST_UNION_AGG`で交差形状を統合する例を示すが、これは既存バッチの単純合計とは別の改善例である。

災害種別・想定条件を集計キーに残す。地域別の部分結果を被覆率のMAXだけでまとめても、全体の和集合にはならない。

## 境界と欠測の確認

125mメッシュは緯度経度で定義され、全国一律の125m四方ではない。メッシュコードと計算に使う境界を一致させる。データ対象外・未取得・変換失敗・非交差を区別し、行がないことを安全と解釈しない。元のポリゴンと出典を残し、集計値から住所単位の状況を復元できるとは説明しない。

## 面積の割合と人口の割合は同じか { #population-apportionment }

「店から500mの円」の人口を知りたいのに、元の統計が町丁目単位しかないことがある。境界をまたぐ町丁目の人口を、円の内外に推計で配り直す処理を**按分（あんぶん）**という。

説明用の例として、人口1,000人の区域の面積40％が円に入る場合を考える。

| 方法 | この例での扱い | 仮定・注意 |
| --- | --- | --- |
| 代表点で選ぶ | 代表点が円内なら1,000人、外なら0人 | 区域内の人口分布を考慮しない |
| 面積で配る | 1,000 × 40％ = 400人と推計 | 区域内の人口密度を一様と仮定する |
| 居住分布を使う | 居住地の位置や重みに応じて配る | 住宅の分布などの補助情報が必要。結果はその品質や時点にも依存する |

400人は円内で数えた実測人数ではない。円に入る部分が公園や工場中心なら、面積だけの推計は偏り得る。一方、補助情報を使っても個人の居住位置を正確に特定したことにはならない。EsriのBusiness Analystは居住分布を表す重み付き点を使う方式を説明しているが、国・データにより方法は異なる。

報告には「元の統計の年と区域」「集計した範囲」「按分方法」を添える。細かな地図で表示できることと、統計がその細かさで観測されていることは別である。区切り方への依存は[MAUP](../concepts/maup.md)にも関わり、按分だけでは解消しない。なお、被覆率は面積の割合を求める処理、人口按分はその割合などを使って属性を推計する処理である。
