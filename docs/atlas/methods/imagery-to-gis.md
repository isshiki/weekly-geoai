# 画像からGIS情報を作る解析と検証

画像解析では、画素を観察・加工する段階と、抽出結果をGISレイヤーとして使う段階を分ける。画像の補正や指数計算は通常の画像処理でも行える。AIを使う場合は、何を分類・抽出したいかを先に決める。

## 土地・建物・変化のどれを知りたいか

衛星画像は、場所・撮影時期・観測する波長を持つデータである。森林の広がりを調べるのか、建物を一棟ずつ見つけるのかで、必要な画像と出力は変わる。

| 知りたいこと | 出力の例と読み方 |
| --- | --- |
| 森林・農地・水域はどこか | 土地被覆図。画素ごとに種類を付ける処理は、画像分野ではセマンティックセグメンテーションとも呼ばれる |
| 建物がどこにあり、どんな形か | 物体検出は位置を矩形で示す。輪郭まで必要なら、画素ごとに対象を分ける領域分割を使う |
| 前後で何が変わったか | 異なる時期の画像を比較する。季節・雲・撮影条件による違いと、知りたい変化を区別する |

例えば1画素が地上10mに相当する画像では、小さな建物の正確な輪郭を取り出すには細かさが足りない。AIの種類を選ぶ前に、対象の大きさに合う地上解像度を確認する。植生の状態を見るNDVI（正規化植生指数）の計算には、学習済みAIモデルは必要ない。指数やしきい値で足りる目的には、それらも比較の基準にできる。

近隣の似た画像を学習用・評価用へ無作為に振り分けると、別地域での性能を高く見積もるおそれがある。地域や時期を分けるだけで十分とはせず、利用予定の場所・季節・センサーに近い条件で確かめる。詳しい評価設計は[分析結果の検証と適用範囲](spatial-analysis-validation.md)を参照する。

## 入力から検証まで { #workflow }

| 段階 | 確認すること |
| --- | --- |
| 入力 | 観測日、センサー、バンド、解像度、CRS、雲や欠損。正解データの作り方と時点も確認する |
| 処理 | 画像の分類、物体の検出、画素ごとの領域分割のどれが目的に合うか |
| 出力 | クラス名、検出位置、分類ラスター、抽出ポリゴンなど。スコアの意味も残す |
| 検証 | 誤検出・見逃し、地域や時期による差、GISレイヤー化した後の位置・形状 |

## 学習用の正解も点検する

学習データのラベルは、人が付けた対象の種類・位置・輪郭である。建物の角が欠けたり、別の種類が付いていれば、学習前に修正する。画像をまとめて眺め、地図上の対象とラベルを対応付けて確認する工程を設ける。

製品例では、ArcGIS Pro 3.8のImage Analystが、画像フォルダー・モザイク全体のレビューと地図上のラベル修正を強化した。物体検出のCOCO・YOLO形式や、地球観測画像向けの特徴抽出モデルEO-DINOにも対応する。形式を読み込めることと、ラベルやモデルが目的に合うことは別に確認する。CUDA 13対応では既存GPUとドライバーの互換性にも注意する。

## 「見つけた数」だけで評価しない

建物抽出なら、実在しない建物を抽出した誤検出と、ある建物を抽出しなかった見逃しを分ける。適合率（precision）は予測した陽性のうち正しかった割合、再現率（recall）は実際の陽性のうち見つけた割合である。画素を数えるか、建物を一件ずつ数えるかで評価単位が変わるため、先に決める。

領域の重なりにはIoU（共通部分の面積 ÷ 和集合の面積）などを使える。建物単位の評価では、予測と正解を同じ建物とみなす対応規則も必要である。全体の一つのスコアだけで、境界のずれや小さい対象の見逃しを説明できるとは限らない。

これらは検証設計の案内であり、特定モデルの実測結果ではない。[地域・時点を分ける検証](spatial-analysis-validation.md)と[来歴の記録](../data/geospatial-record-provenance.md)も併せて行う。

## モデル入力と元の地物の対応を残す

SpatialArrowの紹介記事は、元の地物ID・形状・CRSと、モデルに渡す画像・ラベルの変換を対応付ける設計を示す。切り出しや拡大縮小を画像とラベルに同じ条件で適用し、元の座標へ戻すための情報も残す。GeoParquetやGeoArrowを採用するだけで、この対応が自動的に保証されるわけではない。

屋根上の太陽光パネル検出では、RF-DETR MediumのmAP@.50:.95が56.97％から59.35％へ改善したと報告する。ただし文脈範囲やサンプル頻度なども変わる比較であり、一要因の効果とは断定しない。画像上での評価件数は地図上の重複を除いた施設数ではなく、復元後の位置精度・地物の同一性・重複除去は別途確かめる。本Atlasでの再実行は行っていない。

## 画像の変化を行政の確認候補へつなぐ

韓国・始興市のグリーンベルトを扱う研究は、衛星・航空・ドローン画像の変化検出、YOLOv8による構造物抽出、SegFormerによる土地被覆分類を、地籍・行政記録へ結び付ける。画像から分かる物理的な変化と、許可の有無などの法的な状態を分けて扱う設計である。

研究では2,486筆を確認候補とし、手動判読の1,836件より35.4%多かった。ただし、候補が多いことは違反確定件数や再現率が35.4%改善したことを意味しない。現地確認と行政側の判断が必要になる。研究内の評価を別地域での性能保証として扱わず、本Atlasではモデルの再実行も行っていない。

## 街路画像のスコアを元画像で確かめる

2026年10月19日の「住みやすさマップ」制作記事は、Mapillaryの画像から人の多さ・明るさ・緑・歩道を数値化する際に見つかった誤りを報告する。東京エリアのベータ版であり、スコアは実際の治安や住み心地を保証するものではない。

| 観察された誤り | 作者の対処 |
| --- | --- |
| 一部の撮影時刻の9時間ずれで昼を夜と判定 | 画像中の空の明るさから昼夜を判定 |
| 緑の看板を植物と数え、日陰の木を見落とす | 色だけの集計から木・植え込みの識別へ変更 |
| 連続写真の同じ通行人や撮影者を重複計上 | 15秒以内の画像を除外し、撮影者の除外範囲も修正 |

これは作者が実施した改善の報告である。15秒という間隔を万能な重複除去条件とはせず、修正後の誤検出・見逃しも確認する。Atlasではアプリの再検証は行っていない。画像が少ない地域は参考値とする表示や、何を測るスコアかを説明する工夫を参照する。

## 道路の映像から設備台帳の候補を作る

道路を撮影した映像から標識などを見つける場合、画像に写った対象の検出に加え、地図上の位置と同じ設備の重複を確認する必要がある。

ArcGISの2026年11月の線形参照機能の紹介では、映像から地物を抽出するベータ機能が示されている。文章で対象を指定するSAM 3による抽出と、複数フレームを使う位置付け・重複除去を組み合わせ、利用者が誤検出や分類を確認してから結果を採用する。

線形参照は「道路の起点から何m」のように、路線上の距離で位置を管理する方法である。画像の認識と道路上の位置管理をつなげても、見逃した設備や位置の誤差がなくなるわけではない。正式な設備台帳へ反映する前に、元映像と現場の情報で確認する。ここでは公式紹介を確認しており、製品操作や抽出精度の検証はしていない。

## 波長の似ている場所を探す解析

ハイパースペクトル画像は、多数の波長帯で地表の反射を記録する画像である。現地で確認した樹木の反射特性を基準に、似た画素を探す使い方がある。

Esriのオーク分布の例では、425バンドのAVIRIS画像から現地51地点の平均スペクトルを作り、ArcGIS Onlineで一致度を計算する。0.993を超える画素を抽出し、取り分けた9地点との重なりを目視で確かめている。0.993は正解率99.3％を意味せず、この画像で選んだしきい値である。

この例のSAMはSpectral Angle Mapper（スペクトル角による比較）の略で、画像領域を分けるSegment Anything系のモデルとは別物である。スペクトル比較も画像解析の選択肢として捉え、別の季節・地域へしきい値をそのまま移せるとは考えない。
