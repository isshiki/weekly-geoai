# 空間索引の選択と評価条件

空間索引は、位置や範囲に関する検索で調べるデータを絞るための仕組みである。索引の選択では、2D・3D・点群という対象と、検索や更新の条件を分けて比較する。

## 候補を絞る処理と、形状を判定する処理

全店舗と全区域を比較する前に、区域を囲む矩形（bbox）などで候補を減らす。矩形が重なっても、実際の形状が交差するとは限らない。候補を得た後、目的に合う形状の条件で確認する。

ShapelyのSTRtreeは、構築時に登録した形状の2次元bboxを使う索引である。`query`は条件を指定しなければbboxの候補を返し、`predicate="intersects"`などを指定すると形状の判定も行う。Z座標は索引のbbox判定に使われず、構築後に要素を追加・削除するものでもない。これらはこの実装の仕様であり、すべての空間索引に共通する制約ではない。

## 選ぶ前の確認

| 確認すること | 判断への影響 |
| --- | --- |
| 問い | 範囲内、交差、最近傍では必要な検索が異なる |
| 次元と形状 | 2D・3D、点・線・面、密集度を確認する |
| 更新 | 一度作って繰り返し読むか、追加・削除が多いか |
| 出力 | 候補IDなのか、形状判定まで済んだ結果なのか |
| 評価条件 | 構築時間、検索時間、メモリ、候補数を分けて測る |

索引を付けるだけでは、CRSの不一致や境界の二重所属は直らない。[4店舗の演習](../guides/spatial-join-exercise.md)で判定の意味を理解し、規模が大きくなった段階で効率化を考える。今回、索引方式間の性能測定は行っていない。

## レビュー論文から確認できた範囲

「From R-Trees to Learned Indexes」の出版社検索表示にある抄録・抜粋は、111研究を統合し、従来型・学習型・複合型を整理する。学習型の評価は2Dや一般的な多次元データに多く、3D地理空間では従来型・複合型が中心と述べる。

密度の偏り、形状の保持、厳密解と近似解の扱い、更新への対応、メモリに収まらない規模、システム統合を設計・評価の論点に挙げている。「学習型なら常に速い」という結論ではない。
