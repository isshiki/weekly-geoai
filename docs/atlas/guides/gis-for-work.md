# 仕事の困りごとからGISを使う

「次の店をどこに出すか」「配送が遅れているのはどこか」。場所によって答えが変わる問いには、地図が役立つ。GISは、場所を手掛かりに情報を整理・重ね合わせ、比較や判断に使う仕組みである。特定の製品名ではなく、コードを書くことも参加条件ではない。

## まず一つの判断を選ぶ

以下は使い道を考えるための架空例であり、導入効果を実証した事例ではない。最初は一地域・一業務に絞ると、必要な情報を確認しやすい。

| 担当者の疑問 | 地図で見比べる情報 | 次の行動と、まだ分からないこと |
| --- | --- | --- |
| 出店：候補AとBのどちらを詳しく調べるか | 周辺人口、競合店、駅・道路からのアクセス | 現地調査する候補を絞る。競合が少ないだけでは需要や売上は分からない |
| 営業・販促：どの地域で提案を変えるか | 得意先の実績、周辺の世帯構成、未訪問の地域 | 提案や訪問先を考える。地域の平均像が、その店の顧客像とは限らない |
| 配送：予定に間に合うか | 訪問先、道路、到着予定、車両の現在地 | 順序や担当を見直す。車が到着したことと作業が完了したことは別 |
| 施設管理：どこから点検するか | 施設台帳、点検記録、災害の想定区域 | 確認が必要な施設を抽出する。区域に入るだけでは損害額は決まらない |
| 建設・用地：周辺条件を先に把握したい | 土地利用、地形、道路、既存の建物 | 調査項目を整理する。地図だけで境界や建築の可否を確定しない |

たとえば出店担当者なら、最初の成果物は「売れる場所を自動で決めるAI」でなくてもよい。候補2か所について同じ範囲・同じ時点の情報を並べ、現地で確かめる項目を整理できれば、次の判断につながる。

## 地図に載せる情報を分ける

**場所の情報**は店舗・道路・区域など、**その場所の状態**は売上・人口・点検日などである。店舗番号で売上表を結ぶ方法もあれば、「この区域の中にある店舗」という位置関係で結ぶ方法もある。異なるデータに共通の番号が必ずあるわけではない。

画面の地図画像と、集計できる元データも区別する。眺められる画像があっても、店舗の分類や区域の境界をそのまま集計できるとは限らない。まず[POIデータ選び](poi-workflow.md#business-data)で、手元の情報と不足する情報を分ける。

## 「見える」「予測する」「効果が出る」は別

| 段階 | 例 | 確かめること |
| --- | --- | --- |
| 状況を整理する | 店舗の位置や周辺人口を並べる | 更新日、抜け・重複、範囲の定義 |
| 比較・予測する | 候補地を比べる、将来の売上を推定する | 比較条件、予測の外れ方、別地域でも通用するか |
| 行動して振り返る | 販促や配送計画を変更する | 実績と比較対象。変更後の改善を、変更だけの効果と決めつけない |

通常のGISでも表示・集計はできる。AIには操作の補助や資料整理、予測モデルによる分析などの役割があるが、AIを使ったこと自体は正しさの証明にならない。「何を決めたいか」「何の情報が足りないか」を先に言葉にすると、道具を選びやすい。
